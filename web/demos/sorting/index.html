Sorting, Staged

Eight bars, out of order. An insertion sort walks the fourth bar left past its larger neighbours, then the fifth, then the sixth — twenty-one seconds of theatre in which every comparison lights a tick and every swap moves two bars. Nothing on this page is hand-animated: one build-time function emitted the entire timeline.

01

The overture

A title card, one promise: every comparison and swap below is emitted at build time. That is the difference between this demo and a sorted-bar screensaver — the choreography you are about to watch falls out of running the algorithm, the same way a compiler's output falls out of source.

02

The function behind the play

Animatix timeline functions run at build time: they execute while the scene compiles, and every action they emit becomes an ordinary keyframe beat. This one carries the algorithm's own state — order[k] tracks which original bar occupies slot k, so each swap targets the bars currently in the two slots being exchanged — and the [step:] modifier advances a build-time clock, so the nested loops pace themselves. 

fn insertion_sort(bars, values: List<Num>, comp_ticks, swap_ticks) {
  let order = {0, 1, 2, 3, 4, 5, 6, 7}
  for key in {1, 2, 3, 4, 5, 6, 7} [step: 2400ms] {
    key_note.target = bars.bar[order[key]] [300ms]
    for j in {0, 1, 2, 3, 4, 5, 6} [step: 300ms] {
      if j < key {
        fade-in comp_ticks.t[ci] [120ms]
        if values[order[key - j]] < values[order[key - j - 1]] {
          swap bars.bar[order[key - j]], bars.bar[order[key - j - 1]] [260ms]
          // …advance the counters, update `order`…
        }
      }
    }
  }
}

The bars and the tick strips are components (Bars, Ticks) whose children are generated by for over the input list — so the whole page is data-directed: change the values array and the function stages a different performance.

03

The performance

And this is that function, played. The amber callout is the key — the bar being inserted; it slides left past every larger neighbour while the blue comparison ticks and the gold swap ticks tally the work. Watch the smallest bar (value 5) slide from the middle to the front in three comparisons and three swaps — it is the bar that travels furthest — while the tallest (93) is pushed right by every later key and finishes at the far edge.

04

The finale, and the bill

The same eight bars, re-staged sorted — the component instantiated again with the values in order, green for the curtain call. And the bill, stated honestly: insertion sort spends O(n²) comparisons for O(1) extra memory. Beautiful as theatre, impractical at scale — which is the other thing a good explainer should say out loud.
