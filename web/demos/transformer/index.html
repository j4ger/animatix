The Transformer Architecture, Animated

Six short animations that build the transformer up piece by piece — tokens, positions, attention, multi-head attention, the feed-forward block, and the full stack. Each figure is a declarative scene file, compiled in your browser and drawn with WebGPU.

01

From text to tokens

A transformer never sees words. Text is split into tokens, and each token is replaced by a learned vector — its embedding. Everything downstream operates on those numbers, never on the words.

02

Positional encoding

Attention has no built-in sense of order, so each position is stamped with a fingerprint built from sine waves of growing wavelength. Move a word and its vector changes, even though its embedding doesn't.

03

Self-attention

The core idea. The token “it” asks a question (its query); every token answers with a key and offers its content (a value). A softmax over the query–key scores decides how much of each answer it keeps.

04

Multi-head attention

One attention pattern is rarely enough, so the model runs several in parallel. Each head is free to specialize — grammar, references, neighbours — and the outputs are concatenated and mixed back into a single vector per token.

05

Feed-forward & residuals

Attention moves information between tokens; the feed-forward network then transforms each token on its own, widening 4× and projecting back. Skip connections keep the original signal one hop away, so depth refines instead of erasing.

06

Stacking the blocks

One attention-plus-FFN block is a layer. Stack N of them and tokens flow up the tower, arriving at the top contextualized and ready for a language-modeling or task head.

How this page works

There is no video here and no backend. Each figure loads a .amx text file at runtime, compiles it in the browser, and renders it with WebGPU. All six share one engine download and one GPU device, and a figure that scrolls out of view pauses itself. 

<script type="module" src="../../embed/amx-player.js"
        data-runtime-base="../../pkg-slim"></script>

<amx-player src="scenes/attention.amx" autoplay loop controls
            hold="1.5"></amx-player>

The scenes use plain text only, so the page serves the playback-only pkg-slim profile instead of the full engine — 1.1 MB against 7.8 MB over the wire. The full profile is only needed for Typst markup, equations and image or SVG assets.

hold is the pause before a looping figure restarts. A scene's timeline ends at its last keyframe, so without a hold the finished diagram would cut straight back to an empty stage; the player rests the finished frame, then dissolves it out and back in.

The scene sources are plain text — click any .amx ↗ link above to read one, or open the QA page.
