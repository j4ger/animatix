# Isolated large-input splitter resource probe

Experimental branch only: `experiment/splitter-resource-20261117`. Do not merge
this workflow into main. It has exactly two jobs and no deploy/release path.
No user workstation build is involved.

1. `input` builds one full Animatix **wasm-dev original input**, with main's
   existing opt-level1/debug/fat-LTO/CGU1 and relocation/debug flags unchanged.
   It runs pinned wasm-bindgen with explicit `--out-name animatix_web`. It does
   not assemble, publish, or verify a full SDK. Raw input, four bindgen files,
   and a bounded identity/hash manifest are the only build artifact.
2. `split` downloads that exact same-run artifact ID from its successful input
   job, not a latest artifact/name search. It verifies exact file inventory,
   no symlinks, sizes, SHA256, Wasm header, repo/ref/commit/run/attempt, lockfiles,
   compiler versions, flags, and candidate patch digest before building tools.
   Rerun the whole workflow if needed: an isolated split-job retry with a newer
   run_attempt deliberately rejects the previous attempt's input.
3. The same runner builds baseline and candidate host binaries from the same
   checkout/toolchain/profile. The only candidate difference is the reviewed
   allocation-lifetime patch in this folder (two exact vendored paths).
   No wasm-dev profile A/B is mixed into the comparison.
4. Same input bytes, `RAYON_NUM_THREADS=1`, order A/B then B/A. A guarded or
   failed first pair is not repeated. Split timings exclude compilation,
   wasm-bindgen, and wasm-opt. Output comparison is on normalized Wasm plus
   JS/JSON after validation with the existing wasm-opt -Oz/strip-debug step.
   Raw hashes are also recorded. Normalized equality is NOT browser/SDK
   acceptance, nor proof that dev DWARF is preserved. Those flags remain false
   in the result. No browser sandbox bypass or browser test is used.

## Safety and resource limits

Only this exact branch push triggers the workflow. Other branch/tag/production
workflow trigger definitions are checked in contract tests. Contents permission
is read-only; checkout does not persist credentials. No OIDC, production secrets,
Rust cache or Cachix write action is configured. Nix substituters are read-only.
The pinned Determinate installer action normally caches its installer download;
we instead download the official v3.24.2 executable with release-verified SHA256
and use its `source-binary` route, which returns before the GitHub-cache code.
Pinned nix-installer-action package-lock resolves detsys-ts2.1.4; its
src/index.ts/fetchArtifact confirms this early return. The action's GitHub token
is empty, KVM setup off, and runner-user trust off. No extra flake trust granted.
Artifacts expire after one day. Only bounded evidence JSON/logs are retained
from splitting; generated split modules and entire target/cache trees are not
uploaded. Input upload is capped to1.5GiB aggregate, original<=1GiB and each
bindgen file<=256MiB. These are generated by this same trusted job, not an
arbitrary external ZIP; the download action handles extraction and our manifest
validation checks its result before use.

Preflight requires at least13GiB MemAvailable. Process-group summed RSS is
sampled every0.2s (shared pages may be counted twice); this is NOT a hard memory
reservation or an assurance against OOM. Split budget12GiB/600s per invocation;
input compile10GiB/3600s; bindgen6GiB/300s. Available-memory<1.5GiB, free-disk<2GiB,
and excess logs also stop work. Before any command at least3GiB disk is required.
SIGTERM/INT are forwarded to the new child session; wait/TERM/KILL cleanup covers
descendants and persists non-success evidence. Whole-job timeouts are80/70min.
No RLIMIT_AS is used or mislabeled as RSS. The cumulative rusage field is not a
per-split peak; compare the explicitly sampled process-group measurements.
Logs are truncated to final2MiB and only selected hardware/tool facts are saved,
never an environment/token dump. Resource guard, timeout, tool failure and
unknown SIGKILL are distinct from successful completion; SIGKILL alone is not
called proven kernel OOM. No automatic retry/cap escalation is performed.

## Verification and limits

Run `tools/ci/ci.sh gate splitter-probe-tests` for hermetic contracts. In real
`nix develop .#web-build`, set `SPLITTER_PROBE_REAL_TOOLS=1` so the actual
wasm-bindgen naming test cannot skip. It uses a minimal valid Wasm module and
must produce the exact artifact filenames. The first job runs both pre-Nix
contracts and this real-tool check before the large compilation.

A single hosted A/B+BA is still a small, cold-cache sample. Free disk and actual
runner memory can differ from nominal public-runner specifications; failure
under a guard is useful evidence, not a reason to claim the candidate fixed
full-input splitting. End-to-end SDK integrity, browser behavior, release size,
and normal CI gates remain outside this experimental workflow.

## Second controlled comparison

Both tools now start from the same deterministic data/element-emission source
in this diagnostic commit. The candidate alone additionally applies the
allocation-lifetime patch (production hunks unchanged; the new test fixture
omits the removed field for candidate compilation). A clean tracked tree is required after the baseline
build, the patch and reverse-check must succeed, and source hashes for both
variants are saved. The input identity also binds the common splitter source.

Raw and normalized Wasm section IDs, byte offsets, lengths and SHA-256 digests
are retained before output cleanup. This bounded, streaming evidence can locate
section-level nondeterminism without uploading module bodies. Section hashes are
not semantic equivalence checks; strict normalized whole-file equality remains
the acceptance criterion. Resource budgets, A/B+BA order, no-cache-write and
no-publish boundaries are unchanged. This is still not a full SDK/browser test.
