## 第一部分：animatix Rust 核心

### 🔴 Critical（3 个）

#### 1. Modifier 执行静默吞错

**文件:** `crates/animatix/src/timeline/scene_eval.rs:650,662`

```rust
let _ = self.apply_modifier_bytecode_program(program, ...);
let _ = self.apply_modifier_ir_program(program, ...);
```

IR 和 bytecode modifier 执行返回 `Result<(), EvalError>` 但被 `let _` 丢弃。用户看到的是静默的错误帧，无任何诊断信息。

**修复建议:** 至少加 `tracing::warn!`，最好将错误收集为帧级诊断。

#### 2. `snap.rs` 是死代码（215 行含测试）

**文件:** `crates/animatix-gui/src/app/preview/snap.rs`

文件头标注 `#![allow(dead_code)]`，全 crate 零处导入。`snap_to_guides`, `snap_edges`, `snap_to_point`, `snap_to_grid` 全部未使用。`drag_handler.rs:335-438` 内联实现了相同的 snap 逻辑。

**修复建议:** 将 `drag_handler.rs` 的 snap 逻辑替换为调用 `snap.rs`，或删除此模块。

#### 3. `handle_rename_actor` 静默丢弃编辑错误

**文件:** `crates/animatix-gui/src/app/handlers/actor.rs:58-62`

```rust
let _ = crate::source_edit::apply_edit(stmts, edit);
```

如果 rename 失败（如 actor 不存在），错误被吞掉，函数继续设置"成功"状态消息，误导用户。

**修复建议:** 检查 `apply_edit` 返回值，失败时设置错误状态。

### ⚠️ Warnings（10 个）

#### 4. GPU ping-pong 用指针比较追踪状态

**文件:** `crates/animatix/src/renderer/filter_backend.rs:748`

```rust
src_view as *const _ == tex_a_view as *const _
```

用原始指针地址判断活跃纹理。可行但脆弱——wgpu 内部变更或引用优化可能导致静默错误。建议改用 enum flag 追踪当前活跃纹理。

#### 5. ffmpeg 临时文件 rename 失败时泄漏

**文件:** `crates/animatix/src/renderer/encode/mod.rs:345`

`std::fs::rename` 失败时 `*.tmp_muxed.mp4` 残留磁盘。需在错误路径加 `remove_file` 清理。

#### 6. VM `LoadConst` 无越界检查

**文件:** `crates/animatix/src/timeline/modifier_runtime/vm.rs:264`

```rust
self.stack.push(program.constants[*index].clone());
```

如果字节码损坏（index 越界），会 panic 而非返回错误。`Jump`/`JumpIfFalse` 也有类似问题。

**修复建议:** 改用 `.get(*index).ok_or_else(|| ...)` 返回 `EvalError`。

#### 7. Frame cache 逻辑令人困惑（双重否定）

**文件:** `crates/animatix/src/timeline/scene_eval.rs:617`

```rust
cached.has_child_orders != self.child_orders.is_empty()
```

数学上正确（等价于 `== !is_empty()`），但双重否定极易被误"修复"为 `==`。建议改写为更清晰的形式或存储 count 而非 bool。

#### 8. `needs_frame_env()` 重复调用

**文件:** `crates/animatix/src/timeline/scene_eval.rs:610,639`

同一函数在 cache miss 路径上调用两次，每次遍历三个集合 + `has_procedural_plots()`。第二次应复用第一次结果。

#### 9. 键盘快捷键缺少 `wants_keyboard` 保护

**文件:** `crates/animatix-gui/src/app/mod.rs:419,423`

`Y` 键（ToggleEditorSync）和 `A` 键（Action Palette）在文本输入时也会触发。应加 `wants_keyboard` guard，避免编辑文本时误触。

#### 10. `insertion_palette.rs` 错误未记录

**文件:** `crates/animatix-gui/src/app/shell/insertion_palette.rs:449-450`

`apply_edit` 失败时只设置状态消息，不记录实际错误详情。加 `tracing::warn!` 方便调试。

#### 11. `adelay` 硬编码立体声

**文件:** `crates/animatix/src/renderer/encode/mod.rs:302`

```rust
format!("adelay={delay_ms}|{delay_ms}")
```

假定双声道。Mono 输入会导致 ffmpeg 报错，多声道只延迟前两个。改用 `adelay=delays={delay_ms}` 自动适配。

#### 12. `scene_to_screen` 标记 deprecated 但无属性

**文件:** `crates/animatix-gui/src/app/preview/mod.rs:341`

注释说"已弃用"但仍被 44 处调用。要么加 `#[deprecated]` 属性并迁移调用点，要么删掉注释。

#### 13. Handler 测试覆盖不足

**文件:** `crates/animatix-gui/src/app/command_handlers.rs`

仅覆盖了 UI 类命令（TogglePlayback, ScrubTo 等）。所有域变更 handler（CreateActor, DeleteSelectedActors, RenameActor, Save, OpenFile 等）零测试覆盖。

#### 2. `l3_done` ID 类型混乱（已修复 ✅）

**文件:** `pipeline.py:783` vs `pipeline.py:786`

成功时存 `lesson.id`（= `md5(chapter_id::chapter_title)`），失败时存 `chapter.id`（= `md5(subject::direction::index::title)`），但 `is_l3_done()` 和 `--retry-failed` 始终用 `chapter.id` 检查。导致：
- 成功章节在下次运行时不被识别为已完成，会被重新处理
- `--retry-failed` 对已成功章节做无意义重跑

**已修复:** `mark_l3` 统一使用 `chapter.id`。

#### 3. 文件句柄异常时泄漏（已修复 ✅）

**文件:** `pipeline.py:669-672, 734-735`

`open()` 在 try 块内，`close()` 在 executor 之后。异常时文件句柄泄漏。

**已修复:** 全部改为 `with open(...) as f:` 上下文管理器。
