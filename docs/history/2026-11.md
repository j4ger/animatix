## Author Review, Effect Contract, and Motion Additions (2026-11-01)

This wave made `animatix review` the author-facing automatic review path,
corrected several effect-contract statements that had drifted from the code,
and added the grow/shrink action presets plus three transition shader arms.

### `animatix review`

Added the `review` command as the default automatic authoring gate. The
structural tier builds the target and evaluates sampled `SceneProgram`s on the
CPU with no filter backend, so it needs neither a GPU nor a `verify.txt`.
`--render auto` adds a pixel tier when an offscreen adapter exists; `always`
turns a missing adapter or failed frame into a cannot-run error, and `never`
keeps the run structural-only. The command reports a stable
`schema_version: 1` JSON document (`target`, `render`, `sample_times_s`,
`frames`, `issues`, `summary`) or text, supports `--policy default|site`,
`--samples auto|keyframes|N`, `--max-frames`, `--detail`, `--fail-on`,
`--frames-dir`, `--storyboard`, and `--emit-verify`. Exit codes are 0 (clean),
1 (issue at the selected threshold), and 2 (cannot run).

The default policy ships 11 rules; the `site` policy adds the two
resting-composition rules ported from `scripts/site-rest-check.py`. Rules cover
never-revealed build diagnostics, never-positive opacity, never-on-frame
actors, clipping, independent overlap candidates, text overflow, entrance
visibility, redundant keyframes, blank frames, static beats, and blank
transition endpoints.

### `verify` retained

`animatix verify` was retained unchanged in role: an internal pixel-regression
escape hatch over line-based `verify.txt` checks, not the default authoring
gate. `review` and `verify` share the same `frame_source` pixel helpers, so the
two measurements cannot drift apart. The transformer scene set keeps its
existing 196 checks, and dogfood projects with `verify.txt` keep working; new
projects no longer need one.

### Effect contract corrections

- The built-in catalog is **14 effects**; `examples/animation/30_effects_catalog.amx`
  presents all 14 across **13 `Filter` scopes** (the first cell stacks `Blur`
  then `Bloom`).
- Identity-table and parameter wording was corrected: `Bloom` identity is
  `intensity: 0`, `keep: 1.0`, and `threshold: 0`; a bare `Bloom` is skipped.
- `Bloom` semantics are stated as an **exposure lift** when it runs alone and a
  **glow** after a `Blur`, not a generic brightening or a generic chain `mix`;
  `Bloom.keep` is the effect-specific control for how much of the untouched
  frame stays underneath.
- `LensDistortion.amount` is documented as **scene pixels** (corner
  displacement), joining the six other pixel-unit parameters: `Blur.radius`,
  `ChromaticAberration.offset`, `Sharpen.radius`, `MotionBlur.length`,
  `DropShadow.offset`, and `DropShadow.softness`.
- Region wording now matches the region-scoped backend: scratch targets are
  region-sized, quantized to 64-px steps, and cached; only a whole-scene region
  allocates canvas-sized textures.
- The GPU submit contract is documented per pass: one encoder and
  `queue.submit` per pass, not command-fusion into a single encoder (probe 009
  makes the fused form non-portable). ABI v2 binding 5 (pre-chain original) is
  recorded as resolved.

### Bloom threshold

Added `Bloom.threshold`: a luma gate on the added light. `0` disables the gate
and preserves the historical behaviour; values above `0` let only pixels
brighter than the threshold receive the bloom. The WGSL pass and parameter
schema were extended, and the identity table records the new row.

### `grow-in` / `shrink-out`

Added two pivot-anchored scale presets, bringing the built-in action surface to
**25**:

- `grow-in target [duration, delay, ease, from: ...]` ramps zero → authored
  scale and lifts a hidden-by-default actor without fading one that is already
  visible.
- `shrink-out target [duration, delay, ease, to: ...]` ramps authored scale →
  zero without changing opacity, so a later `grow-in` restores the actor.

Both accept `center`, `left`, `right`, `top`, `bottom`, or a local `(x, y)` as
the pivot. `examples/animation/42_grow_shrink.amx` demonstrates a bottom-anchored
bar rise and a reversible card collapse.

### Three transitions

Added `iris`, `clock-wipe`, and `zoom-through`, bringing the transition registry
to **13** ids. They use shader cases 10–12 and aspect-corrected radial/angular
math (plus endpoint guards that return the outgoing/incoming scene exactly at
progress 0/1). FLIP was explicitly left out of the transition registry: it is
the `shared_id` overlay, not a `play` transition.

### Duplicate-label collision fix

`examples/animation/30_effects_catalog.amx` repeated the child label `img` in
every Filter scope. Actor labels are scene-global in the runtime world, so each
declaration re-parented the single shared image into the later scope; the
earlier cells rendered empty. The catalog and the new
`examples/animation/31_effect_recipes.amx` now use unique child labels
(`img_blur`, `img_grade`, …), and the build emits a `duplicate-label` warning
when an existing label is reused under a different parent. This is the actual
root cause of the apparent multi-Filter ordering problem; the existing readback
fallback for non-tail Filter scopes already preserves painter order. The
zero-readback fast path remains a performance optimization for tail scopes, not
a correctness requirement.

## Web Portfolio v2, and the Engine Defects It Surfaced (2026-11-03)

The web portfolio was rebuilt around a single content source and a house style,
and the work surfaced nine engine/tooling defects that are fixed here.

**Portfolio.** `web/works.json` is now the single source for every showcased
work; `scripts/site-gen.py` generates the page blocks and `content-sync.sh`
gates them. `web/DESIGN.md` records the house style: a constant `StageFloor`
lit at frame 0, `ActHead` / `Caption` / `Readout` furniture, three-act scenes
whose held frame is the fullest composition, type floors (24 px captions,
48–64 px titles), one palette per work and a payoff in every figure. All nine
walkthroughs (38 scenes), the home hero and the language sample were rewritten;
the page language moved to "Observatory Editorial" — serif display, layered
depth, full-bleed 16:9 stages, poster plates and per-work tint — and the tour,
recipes, arena and ambience pages were migrated. Each deck exposes build-time
`let` parameters through a slider rail backed by the player's
`data-vars` / `setVars` (the engine's existing `--set` mechanism). Dev probes
moved under `web/dev/`.

**Deck initialisation bug.** `web/demos/deck.js` inserted its stepper before
`slides[0]` relative to `.wrap`, but the slides live inside
`.deck-slides-container`; `insertBefore` threw `NotFoundError` and killed
initialisation on all nine deck pages — every slide rendered, no navigation
and no lazy-player management. The insert now targets the slides' parent.

**Engine fixes.**
- *Frame-time text.* `RenderCommand::Text` carried the declaration-time
  precompiled `hardware_layout` glyph run whenever no char-progress was set,
  and the draw path preferred it over the frame-recompiled paths, so
  `always { x.text = ... }` rendered the declared string in immediate and
  offscreen frames. The hardware run is attached only when the paths are the
  exact static `Arc`; text assignments clear the static glyph caches.
  `33_count_up_ticker.amx` now reads 23% at t=1.0 in `image` / `storyboard`,
  and a declared+always scene renders exactly one string (no ghost).
- *Conditional actors.* Top-level `if` / `match` statements were dropped by the
  build walk's whitelist: `if n == 2 { a: Rect ... }` checked clean and
  rendered nothing. The walk is recursive and instantiates the taken branch,
  including nested keyframes, loops and array labels.
- *Format specs.* `format("{:.1f} ...")` emitted the braces literally; both
  `{:.N}` and `{:.Nf}` are fixed-point now, and unsupported specifiers warn
  with the actor and specifier instead of rendering garbage.
- *Formatter.* `animatix fmt` deleted every free-standing comment. The
  formatter now reinserts all comment classes from the lossless tokenizer
  (`Formatter::format_source`), and a printer bug that unparenthesized compound
  operands is fixed. CLI, GUI "format document" and LSP share the new path.
- *Layout extents.* Expression-sized (`Auto`) children were measured as zero
  height by Taffy, so mixed rows collapsed toward their centre — the "capsule"
  seen through `gap: 0` bar lanes. Auto/fit now resolve to the measured extent.
  Any container without a fixed `size` publishes its measured content extent
  (Stack = union of layers + padding; Group = union of children), which fixes
  nested `Col`/`Stack` layouts; `Stack align: "start"` now pins the child's
  top-left to the box's top-left instead of its bottom-right to the centre.
- *Instance opacity.* A component instance's `opacity` replaced a root actor's
  authored opacity; it now multiplies through the subtree.
- *draw-in pre-state.* `draw-in` seeded `stroke_progress = 0` only at its
  start time, so the pre-window track evaluated its first keyframe (`1.0`) and
  an authored `opacity: 1` line painted fully from frame 0. The entrance now
  seeds the pre-entrance value; `Line` / `Path` reveal correctly.
- *Ignored `offset`.* A layout-managed child's bare `offset` was dropped
  silently; it now emits `warning[build:ignored-offset]` naming child,
  container and property.
- *Cross-type morphs.* A re-declaration that changes a vector actor's
  primitive (`Rect`→`Ellipse`, `Polygon`→`Path`, …) used to swap the primitive
  at the type keyframe: colour interpolated while the silhouette snapped. The
  already-built start/end path lists in the `vector_paths` track are now drawn
  during the switch window, so geometry and colour interpolate together.
  `strategy: match` radially re-samples closed outlines (square→ellipse keeps
  its width instead of folding through the corner/axis correspondence) and
  drops degenerate closing segments that used to produce a spike.
- *Layout warnings.* `Stack` now emits `warning[build:ignored-stack-gap]`
  naming the container instead of a tracing line nobody saw, and the
  `absolute-position-on-layout-managed-child` message now describes the
  honoured behaviour — `at` / `position` are applied as a manual local offset
  on top of the layout slot — instead of claiming they are ignored.

**Gates.** `scripts/site-rest-check.py` gained the house-style marker contract:
0.80 resting floor plus an absolute 5 % first-frame ink floor, staged so legacy
plates keep 0.35 until rewritten. The transformer verify contract was
regenerated for the 11 s master figure. `content-sync.sh` gained the
manifest/page-blocks check, and the formatter now has repo-wide comment
preservation and AST-stability tests.

## Web playback performance round (2026-11-04/05)

"每个页面只要播放动画就巨卡" turned out to be a controller regression, not a new
engine limit. The symptom was every page laggy whenever a figure animated, while
`web/dev/adaptive-probe.html` reported green.

**Diagnosis.** The per-embed budget controller added the same day fed on the
synchronous CPU time of `render_frame()` — the exact quantity §3.7 already
documents as blind to GPU work (`queue.submit` returns before the GPU draws:
0.49 ms reported for a 3.5 ms frame). Measured on six software-WebGPU embeds with
real rAF: `avgTargetFps 60`, achieved `pageFps ≈ 1.0`, `avgScale` unchanged. The
controller computed `target = 60`, `floorTooSlow = false` on every machine and
never lowered cadence or raster. A second blind spot: a single >200 ms gap was
treated as exogenous and reset the clocks, so a software adapter delivering
~1 rAF/s was permanently invisible to adaptation. And the manual-tick probe
synthesised a perfect 16 ms cadence, so it could not expose GPU saturation at all.

**Landed (embed, plus one engine cache refinement).**

- **Real frame-pressure signal.** `core.js` tracks a gated missed-vsync ratio from
  rAF timestamp gaps on the committed 60 Hz steps (wall-clock window, so a
  ~1 rAF/s machine still fills it), excludes a single >200 ms stall / scroll /
  hidden tab, and drives a page-wide **cadence ladder** `[60,50,40,30,24,20]`.
  fps before raster: lowering the rate costs no sharpness; lowering resolution
  blurs. `_costMs` is demoted to a relative weight. A scale trial is judged by the
  pressure ratio, not CPU encode time (which is resolution-insensitive, so the old
  check always declared trials ineffective and permanently disabled raster
  reduction). Per-embed phase offsets + a per-tick render cap stop N figures
  rendering in one tick.
- **HiDPI cap.** `_displayGeometry` supersamples only to 1.5× / 2 MP; Rust
  `render_scale` defaults to 0.85 so the pre-JS frame is not 2× on Retina.
- **Shell-side held-frame dedup.** The embed skips the `render_frame` call (not
  just the raster) when a loop's held frame has not changed, with a 500 ms TTL so
  an external canvas clear cannot freeze it.
- **Per-frame DOM hygiene.** `_syncControls` caches the icon/aria/chip and writes
  the SVG `innerHTML` only on change (~10 Hz chip); it no longer reparses an SVG
  60×/s on every controls page. `site-chrome.js`'s scroll scrub got a `ticking`
  guard; `deck.js` `setVars` is scoped to the active slide; `arena.js` slider
  seeks coalesce to one per frame.
- **`visibilitychange`** pauses/resumes only the embeds it paused; `rootMargin`
  tightened 200→50 px.
- **Bounded `blend:` layers** (`scene_eval/render.rs`). A `blend:"screen"` actor
  used to push a ±1e9 full-surface layer; it now clips to the subtree's
  world-space bounds when provably safe (leaf, identity transform, no
  camera/mask/effect scope, no child overflowing its parent), and keeps the
  full-surface rect otherwise. `StageFloor`'s glow ellipses (40+ scenes) are the
  target. A container records no own bounds, so it conservatively falls back.
- **Per-subtree static cache gate** (`frame_render.rs`). One `Filter` scope used
  to disable the static-subtree cache for *every* root. The veto is now per root
  (`subtree_has_effect_scope`); fully-static roots keep caching even in a filtered
  scene. `restore_frame_cache`/`store_frame` stay on the conservative whole-frame
  gate. An effect-scope subtree is never cached under a backend, and
  `invalidate_frame_cache` clears the whole cache on every `content_epoch` bump.
- **Clone-free web presentation** (`evaluate_for_presentation` +
  `recycle_presentation_scene`). The web path no longer deep-clones the whole
  `vello::Scene` per frame into the `time_ms`-keyed cache (which never hits during
  animation anyway); it moves the scene out and parks one reusable buffer.
- **Blur downsample** (`blur.rs`). The O(radius) tap walk became a fixed 17-tap
  separable Gaussian whose stride spreads the taps across ±radius. `glass` at
  radius 44 went from 178 to 34 samples/pixel. `support()`/`.pixel()` unchanged so
  `EffectRegion` and `set_raster_scale` stay correct.

**Measured / verified.** `cargo test --workspace` green (GPU-backed render tests
skip — no adapter in this environment); `fmt`, `structure`, `check`, `lint`,
`wasm-check` (both feature sets), `site-scenes` (both profiles), `examples`,
`ext-bench` (9.75 ns), `embed-build`, `content-sync`, `doc`, `no-video`,
`meta-version`, `workflows`, `web-build`, `web-smoke` all pass. `audit` could not
fetch the RustSec DB (network) and no GPU adapter exists for `render-smoke` /
`ANIMATIX_REQUIRE_GPU=1`; both are environmental. **Real-GPU fps remains
unmeasured** — this box delivers no compositor rAF — so throughput acceptance is
still owed on the owner's hardware. Deterministic policy evidence (injected
pressure 60→30 fps, raster untouched, exogenous stall/scroll ≈ 0) is in
`docs/performance_evaluation.md` "The adaptive controller's signal".

## GPU static-layer caching — design (Wave 4, gated, not started)

A browser frame is a full-target vello pass independent of content
(`t ≈ 0.9 ms + 2.8 ns/pixel`). The structural lever is to bake the static prefix
once into a GPU texture and re-rasterize only the dynamic layer. **Go/no-go:** a
GPU capture must first show the residual scales with target area / dispatch count;
if it is a fixed Dawn per-dispatch cost, shrinking the target wins nothing and the
dirty-rect half should be abandoned.

- **Split point.** Add `SplitProgram { static_scene, dynamic_scene,
  dynamic_bounds, bake_eligible, static_root_signature }` and
  `evaluate_split_program_with_debug`, emitted from the existing per-root
  `is_static_subtree_id` walk. Bake only a **leading** run of static roots
  (painter order); a static root after a dynamic one ⇒ ineligible.
  `bake_eligible = false` for `has_effect_scopes`, `camera_used`, a dynamic
  `blend:` actor, or suppressed/transient overrides. Do NOT add fields to
  `SceneProgram` (cloned per cached frame, consumed by GUI/export).
- **Bake/invalidate.** Texture lives on `AmxPlayer`; key `(scene, raster,
  surface_format, document_generation, content_epoch, static_root_signature,
  device_generation)`. New `EngineContext.generation` covers the one uncaught
  case — device loss/recreation (engine.rs:47-63) — which must invalidate all GPU
  state.
- **Composite.** Restore static via a full-target blit, render dynamic into a
  `Color::TRANSPARENT`-cleared texture (the `composite_flip_overlay` precedent,
  transition.rs:547-568), then blit over. No layer drain on baked frames; fall
  back to the ordinary full path if a backend yields pending composites. Disable
  baking for all `BuildTarget::MultiScene`.
- **Dirty rect.** Pinned vello `RenderParams` has no transform/scissor, but a
  sub-region works by re-encoding `Affine::translate(-o)*scale` into a smaller
  target and blitting with `src_rect`; allocate one full-size dynamic texture to
  avoid per-frame realloc. High risk (16-px tile seams; glyph/stroke bounds).
- **`FrameSignature`** gains `static_layer_generation`, `static_root_signature`,
  `surface_format`, `device_generation`; `FrameDedup` must not dedup when the
  static texture is missing/invalid.
- **Phases:** 0 GPU-capture gate + `?amxstatic=1` scaffold; 1 engine split only;
  2 bake+composite (correctness harness, expect a small regression); 3 dirty
  rect; 4 default-on only after ≥20% `page_ms` at pinned scale with same-binary
  and positive controls. Traps: pin `set_render_scale`, disconnect the
  ResizeObserver, pixel A/B has no noise floor.

## Windows `eparts` CI failure — a lockfile feature-unification trap (2026-11-05)

The push after the playback round went red on exactly one job: `eparts
(windows-latest)` (ubuntu and macos passed). The error was in `wgpu-hal`, not
eparts:

```
error[E0277]: the trait bound `windows_core::Error: core::error::Error` is not
satisfied   --> wgpu-hal-29.0.1/src/gles/wgl.rs
```

It is a feature-unification change in `Cargo.lock`, not a code change. `wgpu-hal`
29 depends on `windows-core` with `default-features = false` and relies on some
other crate enabling `std`, which is what pulls in `windows-result/std` — home of
`impl core::error::Error for Error`. `gpu-allocator` 0.28 used to do that: its
`windows` requirement is a range (`>=0.53, <=0.62`) with default features, and
`windows`'s `default = ["std"]`; it had resolved to `windows 0.62.2`. When the
hybrid-bench crate joined the graph the resolver re-unified `gpu-allocator` onto
`windows 0.54` (already present for `cpal`) to avoid a duplicate copy, which
dropped `windows-core` 0.62's `std` feature and removed the impl. Linux/macOS
never see it: only Windows compiles wgpu-hal's WGL/gles backend.

Fix: an explicit `cfg(windows)` dev-dependency `windows-core = { version =
"0.62", default-features = false, features = ["std"] }` in `crates/eparts` (the
only crate the Windows CI builds; `--all-targets` compiles the eframe→wgpu
dev-dependencies). Verified with `cargo tree --target x86_64-pc-windows-msvc -p
eparts -e …features -i windows-core@0.62.2`: `windows-core feature "std"` is now
present where it was absent. This is a workaround for wgpu-hal not enabling
`windows-core/std` itself (29.0.2 still does not) and should be removed when it
does. None of the playback commits touched `Cargo.lock`; the last lock change was
the hybrid-bench commit in the same push.

## Page raster budget and web page baseline (2026-11-05)

The web player's display-matched raster already follows the element's actual
device pixels (CSS size × DPR / `device-pixel-content-box`, capped at 1.5× and
2 MP), but the adaptive controller only reacted to page-wide missed vsync. A
page with several large embeds could therefore sit permanently above its pixel
budget without ever missing a frame. Two additions close that gap:

- `core.js` now sums every playing and visible embed's display-matched raster
  and, above `MAX_PAGE_RASTER_PIXELS = 4,000,000`, scales them uniformly by
  `sqrt(budget / total)`; the result is combined with the pressure ladder via
  `min` so the two budgets cannot compound. `window.__amxPageRasterPixels`
  overrides the budget; `player.displayScale` / `pixelScale` / `rasterPixels`
  expose the split. `data-fps` / `fps` caps an individual embed at 12–60 fps
  (default 60; page pressure can lower it further). The pressure ladder strides
  extra rungs for large rasters (≥1.5 MP: +2, ≥0.6 MP: +1).
- `scripts/adaptive-probe.mjs` gained `AP_PAGE_PIXELS` with a hard
  page-raster assertion, and `scripts/web-page-perf.mjs` is a headed real-GPU
  page-pacing harness (`WPP_ALL_VISIBLE`, `WPP_PAGE`, per-player scale/pressure
  records). On the transformer page with all seven 1109×624 figures visible,
  the budget took the total from a display-matched 10.9 MP (scale 1.30) to
  **4.00 MP** (scale 0.787): p50 6.1 ms, p95 12.2 ms, max 18.2 ms, no frame
  >33 ms at a 165 Hz display. The tour page's 11 visible figures total 3.97 MP
  and keep their display-matched 0.626 scale.

Baseline note: rAF-based page fps is display-refresh-bound (165 Hz here), not a
GPU-cost metric; GPU frame cost stays with `web/dev/perf-probe.html`. The native
quick Criterion baseline (72 benches) was recorded separately on the same commit.

## GPU frame-cost scaling — P1 gate (2026-11-05)

The GPU static-layer caching / dirty-rect item carried an explicit gate: prove
that residual frame cost scales with target area or dispatch count before
building the cache. `web/dev/perf-probe.html` (`debug_bench_frames` + one
`debug_gpu_drain`, real RTX 4060, headed Chromium Vulkan) measured one embed at
five render scales:

| scene | raster area range | fixed `a` | area `b` | R² | max/min `gpu_ms` |
|---|---:|---:|---:|---:|---:|
| attention | 57.6 k – 1.56 MP | 0.75 ms | 0.018 ms/MP | 0.32 | 1.06 |
| plain-fill `scene_rect` | 14.4 k – 389 k px | 1.34 ms | 0.23 ms/MP | 0.11 | 1.06 |

A 16–27× raster-area change moved `gpu_ms` by **less than 0.1 ms**; the fixed
term dominates (the probe's `performance.now` resolution is 0.1 ms). The gate
therefore **rejects** static-layer caching + dirty rect — shrinking the raster
target cannot recover a per-frame/per-dispatch cost. The roadmap item was
replaced by "Fixed per-embed frame cost": reduce per-embed
frames/submissions/presents or share one device/queue, and measure with the same
probe. Caveats: `gpu_ms` is a residual (`per_embed_ms − cpu_ms`); the 6-player
probe variant wedged its Dawn queue and produced no samples, so only one-embed
scaling is measured. Raw data: `target/perf/gpu-scaling.json`.

| `#[test]` functions | 2,376 |
| comment + doc lines | 27,092 (18,866 doc, 8,226 plain) |

Two claims in the review did not survive contact with the tree and are worth
recording so nobody repeats them. First, the "21 test files each re-deriving
`built`/`build_ignoring_warnings`" was wrong: those functions each existed
once. The real duplication was **call-site** boilerplate — 73 `parse_source`
and 77 `build_with_diagnostics` sites, and only 9 files importing the shared
`support` module. Second, the "36 pure-forwarding primitive files, ~6,000
removable lines" was wrong: 32 files implement `Primitive`, but only 10 have a
forwarding `evaluate`, and the rest carry their own `default_props` /
`apply_property` / `apply_defaults` build-time logic. The forwarding layer's
removable share is under 200 lines, not thousands.

What landed, as four checkpoints:

- **Shared fixtures.** `timeline/tests/support.rs` became the single home for
  fixture construction, frame sampling and registry reads (`build`,
  `build_output`, `build_clean`, `build_timeline`, `build_ignoring_warnings`,
  `render_paths`, `baked_paths`, `path_bounds`, `text_at`, the property
  readers, and the `actor`/`keyframe`/`prop`/`vec2` AST builders);
  `build/support.rs` is now only a re-export so `build/*.rs` kept its imports.
  The GUI got `app::test_support`, replacing `handlers::test_support` and the
  hand-rolled store prologues copied into ~27 sites.
- **Micro-test collapse.** `eparts` had 43 single-field `builder_*` tests;
  they are now one `builder_fields` test per widget, with every original
  assertion kept and named.
- **Cross-crate de-duplication.** `crates/animatix/tests/module_tests.rs` moved
  off temp directories onto `ModuleGraph` + `SourceAccess::SourcesOnly` with
  `virtual:///` paths, so its 31 tests no longer touch the filesystem. No test
  was deleted; two (`load_program_with_source_override_does_not_leak_source_map`,
  `with_source_restores_previous_source_after_error`) had to be restored by
  hand after an agent dropped them while converting the harness.
- **Comment compression.** Narratives recounting a debugging session were
  compressed to the invariant plus its consequence, and stale markers
  (`G5/G6 guard`, `#11/#10`, "the split is mechanical") removed.

Measured result: `git diff` across 63 files, **+1,342 / −2,882 (net −1,540)**,
split as test-path files −1,319 and production-path files −221; `#[test]`
functions 2,376 → 2,339. Every production-path change is comment text or doc
text — no production code line changed. `fmt`, `clippy -D warnings`,
`check --workspace --all-targets`, `test --workspace -- --test-threads=1`
(GPU required), `doc` with `-D warnings`, `check-docs.sh` and `structure` all
pass.

**The comment ceiling is real, not a matter of effort.** Of 27,092 comment
lines, only 4,866 sit in test code; the other 22,220 are production, and
16,601 of those are doc comments on public items. `animatix`,
`animatix-syntax` and `animatix-analyzer` compile with
`#![warn(missing_docs)]` and the clippy gate is `-D warnings`, so a public
doc comment is load-bearing: deleting one fails the build. An early pass that
did delete them produced 35 `missing documentation` warnings and was reverted.
Comment reduction is therefore bounded by "how much redundant *prose* the
private items and test files carry", which measured out at ~150 lines, not
the ~2,500 the review projected.

**Two operating lessons for agent-assisted refactors here.** A subagent cannot
compile (no `cargo` outside `nix develop`, and eight concurrent `cargo`
invocations serialize on the `target/` lock anyway), so every wave needs a
repair pass against real compiler output; in this run that pass caught a
`build(...)`-result-used-as-`Timeline` mistake at ~80 sites, one appended
duplicate file body, an invented `DocumentStore::into_document`, and a deleted
local helper whose five call sites remained. And an adversarial reviewer told
to check "did any file outside your list change" against `git status` is
useless when lanes run concurrently — it flagged every other lane's files as
violations. Scope that check to `git diff -- <file>` for the lane's own files.

## GUI document-core merge, and what test "duplication" actually is (2026-11-08)

Two follow-ups to the review above.

**`src/document` and `src/app/document` are now one module.** The tell was a
dependency already pointing the wrong way: `document/rebuild.rs` imported
`crate::app::document::rebuild_output`, so the "lower" module depended on the
"upper" one. They are now a single `app::document`, with the session
(`DocumentSession`, `load`/`save`/`query`/`session_rebuild`/`timing`/`audio`)
next to the GUI-side state (`active_timeline`, `history`, `snapshot`,

became `session_rebuild.rs` to clear the name clash with the background
`rebuild.rs` worker. Import sites: 25 `crate::document::` → `crate::app::document::`;
the 89 existing `crate::app::document::` paths did not move, which is why this
direction was chosen.

Narrowing the merged module to `pub(crate)` (it was `pub`) surfaced dead code a
public module was hiding — worth recording because it is the usual argument for
keeping a module private: `LoadedProgramResult` and `timeline_duration_seconds`
re-exports that nobody used; `DocumentSession::{load, from_source,
set_source_text}` and `timing::timeline_duration_seconds`, all reachable only
from tests (now `#[cfg(test)]`); and three view types carrying fields no caller
reads (`ActiveTimelineRef::{id, composition, scene_name}`,
`ActiveTimelineMut::{id, scene_name}`, `ExportTargetRef::dimensions`,
`ExportScope::Scene`), kept with a one-line `#[allow(dead_code)]` reason rather
than deleted, since they are the resolution vocabulary those types exist to
carry. `animatix_gui::document` was public API that nothing outside the crate
imported; the crate has a lib+bin split, and the bin only uses `run_gui`,
`dev::*` and `fonts::*`.

**Test duplication, measured.** Normalising every `#[test]` body (literals
replaced, whitespace collapsed) and comparing token sets found, within a file,
53 pairs above 0.9 similarity — and **across files in the same crate, exactly
one**, which was not a duplicate (`Row` vs `Stack` handling of an unreadable
`gap`). So the suite has almost no copy-paste left: what looks like overlap
between `tests/ir_tests.rs`, `tests/ir_opt_tests.rs`,
`timeline/tests/variable_tracks.rs` and `timeline/tests/build/bindings.rs` is
four different layers asserting different things about the same *language*
feature.

Table-driving the same-file pairs is also close to worthless as a line
reduction. Six merges survived review (−46 lines, −7 test functions:
`slider`, `actor_edits`, `bar_chart`, `analyzer::symbol_at`, `morph`, and the
`animatix-text` CJK/Latin pair). Eight
were reverted because the table scaffolding cost more than the duplication it

### The `animatix-text` compile-cache flake (2026-11-08)

`cargo test -p animatix-text --lib` failed intermittently: 3 of 8 runs, always
in `tests::caching::compile_cache_keys_on_wrapping_params`, which compared
`Arc::as_ptr` of two compiles to prove the memo table reused an entry. Under
`--test-threads=1` it never failed, which is why the workspace gate (serial by
construction, for GPU teardown) never saw it.

Root cause: `compile_text_cached` memoises into one **process-wide**
`Mutex<HashMap>` shared by the whole test binary. Any other test calling
`clear_text_compile_cache()` — or the 1000-entry cap evicting half the table —
could drop the entry the test was still holding a pointer to, so the second
lookup recompiled and produced a different `Arc`. A `cache_test_guard()` mutex
had been added earlier to serialise the *cache-asserting* tests, but it cannot
work: the cache is also mutated by every test that merely compiles text, and
those never took the guard.

Fix: under `#[cfg(test)]` the two memo tables are `thread_local!` `RefCell`s
(`with_compile_cache` / `with_grouped_cache` keep the production path on the
`OnceLock<Mutex<…>>`). Each test now sees the cache isolation it would get from
its own process, with no ordering discipline to maintain, and the obsolete
`cache_test_guard` mutex plus its 13 call sites are gone. 12 consecutive
parallel runs pass. Production storage is unchanged, and because `cfg(test)`
applies only to the crate under test, `animatix`'s tests still exercise the
global path.

Net: this lever is exhausted. The follow-up pass over the six files in
`crates/animatix/tests/` (3,702 lines, 90 tests) that would be the remaining
candidate reached the same conclusion, and each file's unique coverage was
named rather than assumed: `svg_import_tests.rs` is the only test that turns an
SVG `<text>` element into a `Text` actor; `captions_and_speech_sync.rs` is the
primary speech coverage (`build/speech.rs` has no unit tests); the two `ir_*`
files exercise the IR VM and optimizer, which the AST-evaluator tests in
`timeline/utils/tests.rs` do not; `plot_params_tests.rs` covers plot
*parameter* semantics, not the coordinate math in `timeline/plot/tests.rs`;
`applicability_table_agrees_with_reads.rs` is the property-registry anti-drift
net; `module_tests.rs` was the only end-to-end `ModuleGraph` coverage. Nothing
there is redundant with a unit test, so nothing was deleted. Real test-volume
reduction from here means deciding to stop testing a behaviour — a product
decision, not a refactor.

### Toolchain rewrite: audit / measure / baseline (2026-11-11)

The `verify` mechanism was retired. Its sidecar assertion files asked a human
to hand-compute global times, actor labels and ink thresholds, and asked an LLM
to guess them from imagination; neither could ever say anything about layout
quality, because every check measured ink presence or frame difference rather
than geometry. The replacement follows the shape of the mature tools: facts are
derived by the tool from the scene, verdicts come from rules, intent is declared
in the source, and regression is carried by PNG baselines (Remotion's visual
snapshots, Hyperframes' element-level opt-outs and agent-facing CLI).

Shipped in `3a94d982`: `animatix audit` (one automatic gate, schema v2 with a
compact `--brief` for LLM repair loops), `animatix measure` (pure fact JSON, no
verdicts), `animatix baseline` (snapshot generation, comparison and diff PNGs),
and `storyboard` retained as visual evidence. The old `review`/`verify`
commands, the whole line-based checker module and all eleven sidecar files
(177 hand-written assertions) were deleted. A 27-point probe grid measures
occlusion on the composed frame without a per-actor render; source markers
(`// layout: allow-* - <reason>`) waive exactly one finding code each, with a
non-waivable core list and subtree inheritance. Ten scenes gained 90 baseline
files, and a CPU-only `scene-audit` gate entered `scripts/ci.sh`.

Evidence: every PR gate green in its required shell, 49 CLI lib tests plus
integration tests, both migrated verification scripts passing, and an
end-to-end `--update` / compare / `site-rest-check.py` run. The rewrite also
fixed defects surfaced along the way: marker parsing split `allow-*` on the
first hyphen, an off-by-one in the analyzer's 0-based declaration lines, a
persistence rule that downgraded nearly every finding to `info`, a
`generated` policy that never fired, lost `--frames-dir` output, and a baseline
key collision between three projects all named `entry.amx`.

Accepted trade-offs, deliberately not closed here: the internal Rust module
keeps its `review/` name (only the user-visible command surface changed);
`--evidence` writes per-sample frame PNGs rather than per-finding crops, since
the render tier does not retain RGBA buffers; the `scene.duration` rule still
reports component-library files as empty when audited standalone, so the
scene walk excludes them. The follow-up round first tried to drive finding
volume down with finer rules and corpus annotation, then deliberately returned
judgement to human visual review; that reversal is recorded in the convergence
entry below.


### Toolchain收敛：判定权回到目视 (2026-11-11)

曾试图通过 `Policy::Generated` 将排版规则自动提升为 Error，并要求语料强制写 ~166 处豁免标记，实践证明该方向不仅给开发带来巨大的 annotation 负担，且 F4 子代理因无法准确从源码推导意图，导致标记与实际排版经常失配，大量标记失效。

本次收敛对齐 Hyperframes 与行业主流视觉审阅工作流：
- **判定权回归**：机器仅负责给出排版事实、证据裁切图与候选警告（Warning/Info），不强行判定视觉美学。`Confidence` 字段因无消费者被删除。
- **工作流对齐**：强调「视觉第一」（PNG/Storyboard 审阅为主，Audit 事实为辅），严禁为了让门禁通过而盲目添加标记。
- **落地改动**：
    - 删除了 `Policy::Generated` 与 `Confidence` 字段；`Persistence` 简化为事实标签。
    - `--evidence` 升级为 per-finding 裁切图，辅助人工快速定位重叠与溢出。
    - `--brief` 输出带证据路径，供 LLM 决策。
    - `scene-audit` gate 不再对 Findings 数量进行严格断言，改为确保硬错误（Hard Errors）为零。
- **持续资产**：前几轮积累的 7 类 relation、聚合上限、render 门控、ECS 角色投影、marker 精确豁免等机制被保留，作为「让机器事实可读」的必要手段。

验收口径：不再要求语料在 `generated` policy 下零 error（该机制已移除）；要求硬错误（如 `build.error`）为零，目视链路可用，报告内容可被开发者消费。

### Vision-first check toolchain (2026-11-11)

转向「视觉优先」校验链，放弃此前以机器兜底排版的尝试。
- **背景**: 机器无法自动判定排版刻意性，F4 标记策略导致 annotation 负担过大且与意图频繁失配。
- **落地**: 实现了 `storyboard` 节拍选帧（区间内渲染候选、取 ink 最大帧；长边 ≤1536）、per-finding 裁切 + 全帧标注证据图、Schema v3（`anchors`/`anchor`/`fix.applicability`）、severity 收紧、`--delta` 增量、`.animatix/audit-budget.json` 棘轮与 `scripts/audit-budget.sh`。
- **规则误报修复**: `entrance.not-visible` 此前忽略动作 `delay`，把「延迟入场尚未结束」误判为缺陷（gradient 一个场景即 13 条）；`actor.ink-missing` / `actor.reveal-missing` 因像素探针无法解析细描边与小组件而报错，现以引擎 `draw_commands` 优先；`actor.never-on-frame` 改用逐帧 padded bounds 相交面积，并跳过装饰层与 `for` 生成子 actor。
- **实测**: 语料 99 场景 `--render never --policy default`：Errors 0、Warnings 1,501 → **8**、Infos 4,804；`--brief` 79 KB/158 findings → 4.5 KB/10 anchors；`24_plot_transitions` contact sheet 空格 4/9 → 0；棘轮预算收敛到 5 个有债文件。
- **试跑证据**: 用五步循环在两处 demo 找到并修复了规则未报的真实缺陷——`examples/composition/25_persistence.amx` 的 `badge` 被 1.4× 相机推离画布（与「persist badge」的演示意图矛盾），`examples/gallery/motion_poster.amx` 的 Ken Burns 章节 kicker 因 `offset: (0,40)` 落到画布上方而不可见。相机演示里刻意出框的 actor 不写标记（会触发 `layout.marker-abuse`），改由预算冻结。
- **机制**: 保留了「视觉事实采集 + 人工审阅 + 源码豁免 + 棘轮预算」的噪音治理闭环，通过目视审阅替代不可靠的机器判定。

- **验收**: 三次提交各自通过全部 24 个门禁与 `transformer-verify`/`dogfood-verify`（10 个基线 hash 变更均经逐帧渲染比对：差异仅 0.006% 的 GPU 亚像素噪声，远低于断言阈值）。预算最终收敛到 4 个有债文件。

## 嵌套 Grid 自动尺寸、Counter 动态前后缀与 ECS 复核（2026-11-13）

承接上轮反馈，两个 Luna 高推理子代理分别实现布局与 Counter 修复，第三个
Luna 子代理独立检查 ECS；主代理复核真实渲染路径、缓存生命周期和统一验证。

### 布局和文字测量

嵌套容器先于父容器构建，之前会把临时宽度当成最终宽度；Grid 的相对宽度
又没有落到单元格，Col 的跨轴 fill 则误用 flex-grow。现在 Grid 在有相对宽度
子项时，按扣除 padding/gap 的可用宽度分配等宽列；Col 跨轴 fill 使用内容宽度。
子容器从父级已解析的 layout_size 取约束，避免旧 size 轨道重新撑宽后代。
Row/Col 原有百分比尺寸基准保持不变，跨轴 fill 的修复单独处理 padding，
既有 25%-of-900 的 Row 用例仍按 225px 验证。

文字宽度传播延后到上层约束确定，再向下测量、向上汇总自动高度和行间距。
固定轴及显式 text_max_width 保持权威。每次重排沿树进行一次有限遍历，深度
超过 64 给出 LayoutSizeFallback，保留先前测量；没有迭代求解尺寸循环。
重新编译同时清除旧静态字形、硬件排版与裁切缓存，避免字段更新却仍播放
声明时未换行的字形。回归同时检查真实路径、宽度、换行高度和 18px 行间距。
同时移除声明时的 local_bounds 缓存，让精确边界与拾取使用实际换行命令；
无法断行且超过可用宽度的内容发出明确诊断，保留 authored overflow 和字号。

### Counter

逐帧采样 prefix/suffix 和字体属性，前后缀变更只编译变化的符号，复用已有
有界文本编译缓存；静态数字字形借用原始数据，字体变更才构建匹配的字形集。
数字与符号路径统一放在 advance 槽中心，修正前后缀与数字/逗号的偏移和重叠；
平移同步更新缓存 glyph bounds，避免每帧重算曲线极值。裁切与精确边界随
采样路径更新。未显式指定的格式/前后缀默认值写入实体 TaggedTracks，防止
首次未来关键帧提前影响初始帧。测试包含同字数不同字形、字体替换、关键帧、
always、反向 seek、克隆和内存 carry。

### ECS 证据与边界

新布局重排入口统一调用 invalidate_frame_cache，再执行递归组件写入。
新增测试先填充帧缓存，再验证重排使 epoch 前移并清缓存；另一项测试验证
Timeline 克隆保留 EntityId、层级、size/color 组件，重置临时缓存，克隆侧
编辑不清除原 Timeline 的缓存。Counter 新配置仍在 World 的 TextTracks /
TaggedTracks 中，未新增按 label 索引的实体旁表，没有改变 BehaviorDef 分派、
组件存储、快照格式或引擎/渲染器依赖方向。

审查还确认一个既有边界：CounterData 已使用 serde(skip)，内存 carry 会保留
字形缓存，序列化后恢复则尚未重建它。此项列入 roadmap；不能用内存 carry
测试或普通字段的 serde round-trip 宣称已覆盖序列化后的 Counter 渲染。
组件包装 Group 下的固定宽/auto 高 Col 会先独立换行，再由 Group 发布内容
并集，因此仍适用本轮修复；跨 Group 继承外层 Grid 的相对 fill/percentage
槽位则需要另定结构容器契约，已单列 roadmap，没有宣称通用 Group 重排已实现。

探针为 [nested-grid-counter-2026-11-13.amx](../../dogfood/probes/nested-grid-counter-2026-11-13.amx)，
用 --set W=420 / W=840 比较窄、宽布局，采样 0、1.999、2、3 秒。
本地原始证据目录为 target/perf/sizing-counter-2026-11-13/。
