## Author Review, Effect Contract, and Motion Additions (2026-11-01)

This wave made `animatix review` the author-facing automatic review path,
corrected several effect-contract statements that had drifted from the code,
and added the grow/shrink action presets plus three transition shader arms.

### `animatix review`

Added the `review` command as the default automatic authoring gate. The
structural tier builds the target and evaluates sampled `SceneProgram`s on the
CPU with no filter backend, so it needs neither a GPU nor a `verify.txt`.
`--render auto` adds a pixel tier when an offscreen adapter exists; `always`
turns a missing adapter or failed frame into a cannot-run error, and `never`
keeps the run structural-only. The command reports a stable
`schema_version: 1` JSON document (`target`, `render`, `sample_times_s`,
`frames`, `issues`, `summary`) or text, supports `--policy default|site`,
`--samples auto|keyframes|N`, `--max-frames`, `--detail`, `--fail-on`,
`--frames-dir`, `--storyboard`, and `--emit-verify`. Exit codes are 0 (clean),
1 (issue at the selected threshold), and 2 (cannot run).

The default policy ships 11 rules; the `site` policy adds the two
resting-composition rules ported from `scripts/site-rest-check.py`. Rules cover
never-revealed build diagnostics, never-positive opacity, never-on-frame
actors, clipping, independent overlap candidates, text overflow, entrance
visibility, redundant keyframes, blank frames, static beats, and blank
transition endpoints.

### `verify` retained

`animatix verify` was retained unchanged in role: an internal pixel-regression
escape hatch over line-based `verify.txt` checks, not the default authoring
gate. `review` and `verify` share the same `frame_source` pixel helpers, so the
two measurements cannot drift apart. The transformer scene set keeps its
existing 196 checks, and dogfood projects with `verify.txt` keep working; new
projects no longer need one.

### Effect contract corrections

- The built-in catalog is **14 effects**; `examples/animation/30_effects_catalog.amx`
  presents all 14 across **13 `Filter` scopes** (the first cell stacks `Blur`
  then `Bloom`).
- Identity-table and parameter wording was corrected: `Bloom` identity is
  `intensity: 0`, `keep: 1.0`, and `threshold: 0`; a bare `Bloom` is skipped.
- `Bloom` semantics are stated as an **exposure lift** when it runs alone and a
  **glow** after a `Blur`, not a generic brightening or a generic chain `mix`;
  `Bloom.keep` is the effect-specific control for how much of the untouched
  frame stays underneath.
- `LensDistortion.amount` is documented as **scene pixels** (corner
  displacement), joining the six other pixel-unit parameters: `Blur.radius`,
  `ChromaticAberration.offset`, `Sharpen.radius`, `MotionBlur.length`,
  `DropShadow.offset`, and `DropShadow.softness`.
- Region wording now matches the region-scoped backend: scratch targets are
  region-sized, quantized to 64-px steps, and cached; only a whole-scene region
  allocates canvas-sized textures.
- The GPU submit contract is documented per pass: one encoder and
  `queue.submit` per pass, not command-fusion into a single encoder (probe 009
  makes the fused form non-portable). ABI v2 binding 5 (pre-chain original) is
  recorded as resolved.

### Bloom threshold

Added `Bloom.threshold`: a luma gate on the added light. `0` disables the gate
and preserves the historical behaviour; values above `0` let only pixels
brighter than the threshold receive the bloom. The WGSL pass and parameter
schema were extended, and the identity table records the new row.

### `grow-in` / `shrink-out`

Added two pivot-anchored scale presets, bringing the built-in action surface to
**25**:

- `grow-in target [duration, delay, ease, from: ...]` ramps zero → authored
  scale and lifts a hidden-by-default actor without fading one that is already
  visible.
- `shrink-out target [duration, delay, ease, to: ...]` ramps authored scale →
  zero without changing opacity, so a later `grow-in` restores the actor.

Both accept `center`, `left`, `right`, `top`, `bottom`, or a local `(x, y)` as
the pivot. `examples/animation/42_grow_shrink.amx` demonstrates a bottom-anchored
bar rise and a reversible card collapse.

### Three transitions

Added `iris`, `clock-wipe`, and `zoom-through`, bringing the transition registry
to **13** ids. They use shader cases 10–12 and aspect-corrected radial/angular
math (plus endpoint guards that return the outgoing/incoming scene exactly at
progress 0/1). FLIP was explicitly left out of the transition registry: it is
the `shared_id` overlay, not a `play` transition.

### Duplicate-label collision fix

`examples/animation/30_effects_catalog.amx` repeated the child label `img` in
every Filter scope. Actor labels are scene-global in the runtime world, so each
declaration re-parented the single shared image into the later scope; the
earlier cells rendered empty. The catalog and the new
`examples/animation/31_effect_recipes.amx` now use unique child labels
(`img_blur`, `img_grade`, …), and the build emits a `duplicate-label` warning
when an existing label is reused under a different parent. This is the actual
root cause of the apparent multi-Filter ordering problem; the existing readback
fallback for non-tail Filter scopes already preserves painter order. The
zero-readback fast path remains a performance optimization for tail scopes, not
a correctness requirement.
