# Storyboard and internal review

## Fragile beats
- For shared state, write a single record before the cards: `ID | before | event | after`. Include unchanged players and distinguish in-event occupancy from the handed-off state. Mark historical or comparison states as references. Reuse event IDs rather than retyping state.
- For key changes, state the model trigger, readout location, and last-old/first-new delivery evidence. Keep model steps separate from video seconds; when the mechanism is reproducible, link the independent state table. For a deduction, record exactly what is ruled out and which cases remain.
- In construction beats, show the parts connect before testing the result. In a dense sequence check that an interior shot does not imply a premature result or two competing current states. Skip beats that reveal nothing. An illustrative image needs a role and a native fallback only when useful.

## Storyboard review
Use this for confusing intermediate states, concurrency, event-to-narration timing, or a failed first self-check. The author still owns the storyboard. For simple work a separate readback may be enough; use a fresh reviewer with stronger reasoning when a defect could change the teaching or the author and first reviewer disagree. Choose a reviewer with the relevant subject or timing expertise.

1. Give the storyboard reviewer the frozen script, complete scene cards, scene IDs, duration and delivery constraints. They need the intended inference to check whether the directions support it.
2. Ask for **READY / REVISE** with a short list. Each issue should cite the card and cue/time, quote the actual conflicting instruction, name what a viewer could misread, and propose the smallest change and a visible recheck. Separate **blocking** mechanism/evidence/timing errors from optional clarity and polish. A tentative concern is not a confirmed defect. For reasoning beats, compare the stated elimination with the actual evidence; ask for a concrete possibility still consistent with it. For critical events, point to which on-screen readout changes and test the last old and first new expected states against the model step. For timed narration, check the actual locked words between successive cue points, including the lead-in and tail. A readable hold can overlap speech unless the card explicitly places it after speech.
3. Have the author verify the claim against the fixed script and exact cards, then revise. Preserve what is already right. For repeated state claims, recheck the state record, visible action, neighboring handoff and acceptance together. Confirm the exact revised text; a change note is not the check. If a blocker remains, keep the plan internal or state what is unresolved.

Do not treat an internal model verdict as either human approval. The reviewer does not take over narration, storyboard authoring, or production.

## First-look check

Choose a viewer who has not seen the brief, script or storyboard. Start a fresh session for a model reviewer. Give the viewer only the rendered clip or the relevant frames in order, and one neutral question such as “What changed between these moments?” Use neutral filenames. Keep the scene card, expected answer and review notes with the author.

When testing what the picture alone communicates, keep on-diagram labels and hide external narration and captions for that pass. Record the viewer's answer before comparing it with the intended inference. If a viewer attributes a change to a different subject, check where the rendered change actually occurs and whether its placement makes the association clear. Recheck normal delivery with narration and captions restored.

For a disputed reading window, check whether the lead-in already gives away the answer. When it does, a correct answer tests the whole sequence. To isolate the hold, use a question whose deciding detail first appears there. Keep the lead-in, sound and following beat the same across cuts. Give each new viewer one version at normal speed and ask what they saw. Record a response from a still or a replay separately.
