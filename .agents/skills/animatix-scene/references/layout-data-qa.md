# Layout, data and display QA
See the [primitive reference](../../../../docs/primitives.md#barchart) for the target checkout.

- **Layout:** Start from a built-in layout only when it removes work, e.g. a math or metric starter. Keep its relative imports with the scene, choose roles and theme tokens, and inspect the actual viewport. Do not hand a template control of causal geometry. A following endpoint can bind to a suitable actor point, such as child.right in the parent/scene space; verify the connection during motion, not just at rest.
- **Data:** Author values once. Use indexed actors for a repeated series and `scan` for cumulative totals. When labels, marks and history depict the same event, advance them from the same state. Independently timed series can follow their own events. A layout-managed dynamic label may need a box sized for its longest value.
- **Identity in grayscale:** When color identifies a series or state, render the telling moment at its displayed width with `animatix image SCENE --time SECONDS --width PIXELS --grayscale -o OUTPUT.png`. Can you trace a series past the crossing and name it from the key or a nearby label? For a state change, save the before and after frames under separate names and try naming both states. If the distinction is lost, add a cue where the viewer looks: match a line style or marker to the key, or change the label beside a status indicator. Recheck the same frames in grayscale and color.
- **Discrete vs continuous:** Use a discrete data/state change when a new reading is issued. A bare later at write or [0s] alone can interpolate before that marker. Use a shared piecewise state and explicit geometry where a cut is required. The BarChart dataset path is separate; verify the actual frames around a discrete change.
- **Chart scale:** For bars in a linear `Graph`, fix its `y_domain` across states and leave `max_value` at its automatic default. The full domain determines the scale for signed bars. A standalone chart uses its largest positive value by default. Check the zero baseline and the positive and negative bar tips against the painted ticks on both sides of a change.
- **Review:** Pass the actual displayed width to `measure` or `audit`. For a chart embedded in a 360 px column, use `--display-width 360`. For a before/after comparison, use `storyboard --compare` at the delivery scale and choose times where the change should be visible. Their text boxes and stills help find problems; the exported frames still decide whether the marks and labels agree.
